# 全域整合系统重造方案：FDE × 信息部双角色视角

> 作者：贝先生（AI 应用架构师 / 连锁零售 AI 落地负责人）
> 视角：FDE（Forward Deployed Engineer）× 企业信息部
> 场景：天鹅公主 SWAN NOBLE · 47 家门店 · 中央工厂 + 线下门店
> 目标：重造「工厂 → 线下门店」全链路系统对接数据流程，标出 AI 介入点，对标互联网同岗位做法

---

## 一、双角色定位（对标互联网真实岗位）

### FDE（Forward Deployed Engineer）—— 前沿部署工程师

> 源自 Palantir 开创的模式，OpenAI / Salesforce / Databricks 均设此岗，被视为「精英工程单元」。

**互联网真实岗位职责（调研自 Heads / Drivepoint / Mastech 等 JD）：**

| FDE 真实职责 | 在本项目中的对应 |
|---|---|
| 嵌入客户现场，诊断核心工作流瓶颈 | 驻场 47 家门店 + 中央工厂，观察店长/员工真实操作 |
| 从模糊问题到生产级系统，全程负责 | 需求建模 → 系统设计 → 部署 → 稳定运行 |
| AI-native 交付：用 AI 助手压缩交付周期 | 用 AI 加速开发、自动化测试、快速迭代 |
| 配置优先：先最大化平台原生能力，再写代码 | 先打通现有系统接口，而非推翻重来 |
| 数据迁移与集成：接入 ERP/POS/会员/电商 | 对接工厂 ERP、门店收银、公域平台、私域 SCRM |
| go-live 现场驻守 + 训练超级用户 | 上线期间驻店，培训店长和员工，让部署真正落地 |
| 反馈产品团队，沉淀可复用资产 | 把 47 店经验沉淀为方法论、技能包、博客 |

### 信息部（企业信息化/数字化部门）—— 系统对接与数据治理

**互联网/零售企业信息部真实做法（调研自元祖资讯服务部、多乐之日、鸿星尔克案例）：**

| 信息部真实职责 | 在本项目中的对应 |
|---|---|
| 统一主数据：商品编码、会员 ID、门店编号 | 统一口径：门店 47 家、会员 235,542、SKU 一码通 |
| 打通核心系统：ERP / POS / CRM / WMS / 小程序 | 打通工厂 ERP → 门店收银 → 公域 → 私域 → 营运分析 |
| 日清日结：销售单据实时上传，账务清晰 | 收银数据实时回流，次日自动生成经营分析 |
| 供应链协同：中央工厂排产 + 冷链配送 + 门店到货 | 工厂按门店销售趋势排产，智能要货，控制报废率 |
| 数据驱动决策：BI 看板 + 智能报表 | 经营决策平台 + AI 经营分析 + 异常雷达 |

**结论：FDE 管「业务 × AI 落地」，信息部管「系统 × 数据底座」。本项目由一人以双角色贯穿：既做 FDE 的端到端交付与 AI 嵌入，又做信息部的数据打通与系统治理。**

## 二、重造后的系统对接数据流程（工厂 → 门店全链路）

### 全景数据流（重造后）

```
┌────────────┐  生产计划   ┌────────────┐  配送   ┌────────────┐
│  中央工厂   │ ──────────→ │  冷链物流   │ ─────→ │  47 家门店  │
│  生产/排产   │ ←─────────  │            │ ←───── │  收银/POS   │
└────────────┘  要货/报废   └────────────┘  销售   └────────────┘
     │  ▲                                    │  ▲
     │  │ 原料/成本                           │  │ 销售/库存/会员
     ▼  │                                    ▼  │
┌────────────┐  统一数据底座（主数据/口径）   ┌────────────┐
│  ERP 进销存  │ ←──────────────────────────→ │ 私域 SCRM  │
└────────────┘                               └────────────┘
     │                                            │
     └──────────────┬─────────────────────────────┘
                    ▼
        ┌─────────────────────┐
        │  公域平台（抖音/美团） │
        └─────────────────────┘
                    ▼
        ┌─────────────────────┐
        │  营运分析 / 经营决策   │
        │  （次日自动生成）       │
        └─────────────────────┘
```

### 关键对接点（数据从哪来到哪去）

| # | 对接点 | 数据流 | 重造前（痛点） | 重造后 |
|---|---|---|---|---|
| 1 | 工厂 → ERP | 生产计划、原料成本、排产数据 | 靠经验排产，爆款断货/报废率高 | 按门店销售趋势 + 保质期模型自动排产 |
| 2 | ERP → 门店收银 | 商品主数据、库存、价格 | 收银数据晚一天才汇总 | 销售实时上传 ERP，日清日结 |
| 3 | 门店收银 → 公域 | 抖音/美团订单、核销 | 线上线下一盘货对不上 | 公域订单自动同步，库存统一视图 |
| 4 | 公域/收银 → 私域 | 会员 ID、消费记录、积分 | 会员身份割裂，积分不通 | 会员 OneID 打通，全渠道识别 |
| 5 | 全链路 → 营运分析 | 销售/库存/会员/成本 | 人工 Excel 汇总，决策慢半拍 | 数据底座自动汇总，次日生成分析 |

## 三、AI 介入点（哪些地方让 AI 介入）

### AI 介入地图（按环节）

| 环节 | AI 介入点 | 具体做什么 | 价值 |
|---|---|---|---|
| **工厂排产** | AI 销量预测 + 智能排产 | 基于门店销售趋势、节假日、天气、促销，预测每款产品产量 | 计划达成率 ↑，报废率 ↓ |
| **供应链** | AI 智能要货/补货 | 按门店 7 日销售均值 + 保质期模型，自动给出建议要货量 | 缺货率 ↓，库存周转 ↑ |
| **门店收银** | AI 异常检测 | 实时识别异常订单、价格错误、支付断层 | 收银差错 ↓ |
| **公域运营** | AI 内容生产 + 竞品监控 | 自动生成抖音/美团素材、竞品情报结构化入库 | 内容生产 21h→3h |
| **私域会员** | AI 会员分层 + 精准触达 | RFM 八级 + 生命周期四态自动打标，四形态券分层下发 | 复购率月均 +13% |
| **营运分析** | AI 经营分析 + 异常雷达 | 次日自动生成分析，识别假环比/假异常/不可信归因 | 经营分析 66h→4h |
| **门店日常** | AI 知识库问答 | 员工自然语言查标准/查活动/查供应链（LLM×RAG） | 替代翻文档，秒级回答 |
| **决策支持** | AI 行业研究 + 看板自动化 | 行业研究 2 周→1.5 天，看板自动更新 | 年省约 5,800 工时 |

### AI 介入的三条原则（FDE 视角）

1. **先数据后 AI**：口径不统一，AI 算得再快也是错的
2. **AI 做错了要能看出来**：24 条用例 + 检索探针 + 全量回归 + 执行验收分离
3. **门店真的用才算成功**：店长验收 + 使用统计 + 零使用预警

## 四、对标互联网同岗位：他们怎么操作和重造

### FDE 操作流程（互联网真实做法）→ 本项目的落地映射

| 互联网 FDE 操作 | 本项目落地 |
|---|---|
| ① Discovery：嵌入客户现场，诊断工作流瓶颈 | 驻场门店 + 工厂，观察店长/员工真实操作，找出「搬运型工作」 |
| ② 问「用户要做什么决策」再动手 | 先问「门店/总部要看什么数、做什么决定」，再设计系统 |
| ③ 数据迁移与集成（SKU 约定、账户映射） | 统一主数据：门店编码、SKU、会员 ID，一个数一个值 |
| ④ AI-native 交付（用 AI 压缩交付周期） | 用 AI 生成代码、自动化测试、快速迭代系统 |
| ⑤ 配置优先，再写代码 | 先打通现有 ERP/POS/SCRM 接口，不推翻重来 |
| ⑥ go-live 现场驻守 + 训练超级用户 | 上线期驻店，培训店长使用，让部署真正落地 |
| ⑦ 反馈产品团队，沉淀可复用资产 | 沉淀 365 条教训库、28 个技能包、方法论博客 |

### 信息部操作流程（零售数字化真实做法）→ 本项目的落地映射

| 互联网信息部操作 | 本项目落地 |
|---|---|
| ① 统一商品主数据（一码通全店） | 全部门店商品编码、规格、条码一致 |
| ② 统一库存口径（关掉手工 Excel） | 以 ERP 库存为唯一真相源，每周盘点 |
| ③ 打通 ERP/POS/CRM/小程序 | 四条数据源打通，实时同步 |
| ④ 会员全渠道互通（OneID） | 会员 ID 统一，积分通存通兑 |
| ⑤ 供应链协同（智能要货/排产） | 工厂按销售趋势排产，门店智能要货 |
| ⑥ BI 看板 + 数据驱动决策 | 经营决策平台，次日自动生成分析 |
