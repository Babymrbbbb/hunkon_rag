# 从反馈闭环到 CI 门禁：RAG 知识库的生产运维补全

> 一个在 47 家连锁门店真实生产环境运行的 RAG 知识库，继语义缓存与查询改写之后，又补齐了三块生产运维拼图：用户反馈闭环、CI/CD 评测门禁、可视化运维看板。本文记录完整落地过程。

## 背景：生产级 RAG 的「运维三件套」

在《语义缓存与查询改写》一文中，我们已为生产知识库补齐了「省成本」和「提召回」两块能力。但对照市面生产级 RAG 平台（RAGFlow / Dify / FastGPT），仍缺三项运维级能力：

1. **用户反馈闭环**：答案好不好，用户说了算。点赞/点踩数据沉淀为 golden set，驱动评测体系持续演进。
2. **CI/CD 评测门禁**：代码一改动，评测自动跑。召回率低于阈值就阻断合并，防止「改坏不知道」。
3. **可视化运维看板**：缓存、反馈、评测、历史一屏可见，运维不用翻日志。

本文记录这三项的零依赖实现。

## 一、用户反馈闭环：点赞/点踩 → golden set

### 设计

- **存储**：SQLite（`_meta/feedback.db`），表 `feedback`。
- **接口**：`POST /api/feedback` 提交，`GET /api/feedback` 查询（可按 rating 过滤）。
- **前端**：问答页面每条 bot 消息下方自动出现 👍/👎 按钮，点击即提交。
- **golden set 演进**：`export_golden_set()` 只导出点赞过的问答对，可作为评测黄金数据集持续扩充。

### 一个字段顺序 bug

初版 `list()` 方法在组装返回 dict 时，把 `created_at` 错用成了 `reason` 字段的索引（`r[5]`），导致 `time.localtime()` 抛 TypeError，整个 `list()` 被外层 `except` 吞掉返回空列表。修复：`created_at` 在 `r[6]`。这提醒我们：**SQL 字段顺序变更时，取值索引必须同步核对**。

修复后 13 项单元测试全部通过。

## 二、CI/CD 评测门禁：GitHub Actions 自动跑评测

### 设计

作品集仓库 `swan_rag` 新增 `.github/workflows/eval.yml`：

- **触发**：PR 到 main、push main、手动触发。
- **命令**：`python -m app.eval_cli --mock --json --threshold 0.75`
- **`--mock` 关键**：强制离线 MockProvider + 确定性 rule 编译，评测可复现、不受外部限流影响（生产 .env 配置了真实 LLM，直接跑会撞限流）。
- **阻断**：召回命中率低于 75% 时 `exit code 2`，GitHub Actions 判定失败，阻断合并。

### 本地验证

```
python -m app.eval_cli --mock --json --threshold 0.75
# 输出: retrieval_hit_rate 0.875, faithfulness_rate 1.0, passed true
```

## 三、可视化运维看板：零依赖单页

### 设计

在 `kb_web.py` 升级 `/dash` 页面为完整运维看板：

- **数据接口**：`GET /api/dash-data` 聚合返回语义缓存统计、反馈统计、评测报告摘要、最近问答历史。
- **页面**：黑金风格单页，顶部 4 张统计卡 + 评测报告摘要区 + 最近 20 条问答明细表 + 手动刷新。
- **零依赖**：纯 HTML/CSS/JS，无外部库。

## 五、经验沉淀

1. **SQL 字段索引要与取值逻辑同步**：字段顺序一变，所有按索引取值的代码都要核对，否则会被 `except` 静默吞掉。
2. **CI 必须离线可复现**：`--mock` 模式让评测在 CI 上可重复、不受上游限流影响，这是 LLMOps 门禁能落地的前提。
3. **反馈闭环是 golden set 的活水**：用户点赞数据自动扩充评测集，评测从「一次性 24 例」变成「持续演进」。
4. **运维看板聚合已有数据**：不新增存储，只做聚合展示，价值立现。
