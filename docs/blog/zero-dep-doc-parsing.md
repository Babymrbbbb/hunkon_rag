# 零依赖文档深度解析：让 docx、压缩 PDF 与表格进入 RAG

> 企业知识库里大量权威源是 docx、xlsx 和扫描 PDF。纯 Python 标准库能否把它们解析成 RAG 可用的结构化文本？本文记录一次零依赖文档解析增强：docx 段落+表格、PDF FlateDecode 压缩流、xlsx 表格转 Markdown，以及过程中修复的 4 个真实 bug。

## 背景：文档解析是 RAG 的第一公里

在《从离线门禁到生产监控》等文中，我们已为生产知识库补齐了 LLMOps、语义缓存、查询改写、反馈闭环等能力。但一个基础问题始终存在：**知识库里大量权威源是 docx（方案文档、SOP 话术手册、运营分析）和 xlsx（门店数据），之前的解析器只支持 md/txt + 尽力而为的 xlsx/pdf。**

这意味着：
- docx 完全无法入库
- xlsx 只能提取成无结构文本行，字段关系丢失
- PDF 压缩流（大多数电子版 PDF）抽不出文本

本文记录一次零依赖（纯标准库）文档解析增强。

## 一、xlsx：表格转 Markdown

xlsx 本质是 zip+XML。原有实现已能解析 sharedStrings 和单元格，但输出是「空格拼接的文本行」，字段关系不明显。

增强：把每个工作表转为 **Markdown 表格**：

```
| 序号 | 门店编号 | 门店区域 | ... |
|---|---|---|---|
| 1 | 1413 | 肇庆 | ... |
```

这样检索和 LLM 生成都能理解字段关系。真实门店数据.xlsx 验证：6055 字符，字段名+门店明细结构化输出。

## 二、docx：段落 + 表格（新增）

docx 同样基于 zip+XML，核心是 `word/document.xml`。实现：

1. 提取所有 `<w:tbl>` 表格块
2. 从 XML 中**剔除表格块**后提取段落（避免单元格内段落被重复提取）
3. 表格块解析为 Markdown 表格

真实 docx（私域运营现状分析）验证：2188 字符，标题/章节/正文结构化清晰。

## 三、PDF：FlateDecode 压缩流（新增）

多数电子版 PDF 的内容流用 FlateDecode 压缩。实现：

1. 正则匹配 `stream...endstream` 块
2. 若对象含 `FlateDecode`，用 `zlib.decompress`（含裸 deflate 兜底）
3. 在解压后的内容流中抓 `(text) Tj` / `[(text)...] TJ` 文本

测试构造了普通流和压缩流两种最小 PDF，均正确提取文本。扫描件（纯图片）仍无法解析——这是诚实的边界。

## 四、过程中修复的 4 个 bug

### 1. xlsx sharedStrings 索引失效（存量 bug）

原正则 `re.findall(r"<c[^>]*>(.*?)</c>")` 只捕获单元格内容（`<v>0</v>`），**丢失了开标签的 `t="s"` 属性**，导致 shared 字符串永远按数值输出（`0` 而不是「门店」）。修复为匹配整个 `<c ...>...</c>` 再解析。

### 2. docx `w:t` 正则误匹配 `<w:tc>/<w:tr>/<w:tbl>`

`<w:t[^>]*>` 会误匹配 `<w:tc>`（前缀相同），导致捕获内容混入 XML 标签。修复为 `<w:t(?:\s[^>]*)?>`，精确匹配 `<w:t>` 或带属性的 `<w:t xml:space="preserve">`。

### 3. docx 表格内段落重复提取

表格单元格内通常有 `<w:p>` 用于布局，若与正文段落一起提取会重复。修复：先剔除表格块，再提取段落。

### 4. PDF 函数名不一致（NameError 被吞）

`_extract_pdf` 调用了 `_pdf_extract_text_from_stream`（实际函数名是 `_extract_pdf_text_from_stream`），NameError 被 `read_text` 的 try/except 吞掉，导致 PDF 解析**静默返回空**。这类「函数名不一致被 except 吞掉」的 bug 极难发现——测试的 PDF 用例正是为了抓住它。

## 五、验证结果

| 测试 | 结果 |

| xlsx（shared 字符串 + 数值） | ✅ 表格转 Markdown，字段正确 |
| docx（段落 + 表格） | ✅ 段落与表格分离，无重复 |
| PDF 普通流 | ✅ 提取文本 |
| PDF FlateDecode 压缩流 | ✅ 解压后提取文本 |

| 真实 docx / xlsx 端到端 | ✅ 结构化输出 |

## 六、经验沉淀

1. **正则匹配 XML 标签要警惕前缀冲突**：`<w:t>` 会误匹配 `<w:tc>`/`<w:tr>`/`<w:tbl>`，用 `(?:\s[^>]*)?>` 精确收尾。
2. **捕获组要保留判断属性**：解析 XML 时若需要属性（如 `t="s"`），正则必须捕获整个开标签，不能只捕获内容。
3. **函数名不一致会被 except 静默吞掉**：被 try/except 包住的 NameError 会让功能「静默失效」，单测必须覆盖真实调用路径。
4. **先剔除嵌套块再提取同级块**：解析 docx 这类嵌套 XML，先提取表格再剔除，避免段落重复。
