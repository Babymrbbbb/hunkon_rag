# RAG 确定性护栏三模式：把"口径不漂移"做成代码层闸

> 方法论开源复刻，不涉及任何真实业务数据。本文把一组内部工程铁律里
> 与"检索 / 聚合链路正确性"直接相关的三条，抽象成可移植、可测试的通用护栏。

## 为什么需要确定性闸

RAG / 知识库问答最容易出的问题不是"模型不准"，而是**确定性口径在链路里悄悄漂移**：

- 门店总数今天 12、明天被某次生成写成 40；
- 拿 0 个源去问模型，产出一张"空壳页"却能通过字段校验，覆盖掉完整旧版；
- 相关性过滤用字面匹配，"复购提升"搜不到"回购"，相关文档被误杀（内部实战同义召回 25 → 2）。

这些问题靠"提示词里写清楚"压不住——提示词会被覆盖、被遗忘、被改一处漏一处。
正确做法是把口径固化成**代码层确定性后处理**，且落在**每一处实际执行路径**上。

## 模式 A：覆盖闸必须落在每处执行路径

凡"LLM 生成后确定性覆盖"的闸，必须在所有产出对外文本的函数里 `import` 复用同一份
函数。只改一个入口 = 形同虚设——其它入口仍会产出旧口径。

`app/rules.py` 提供 `register_ruling_path()` + `verify_ruling_coverage()`：每个实际输出路径
在调用 `apply_ruling_overrides` 处登记自己，`verify_ruling_coverage()` 在 CI 中证明
"闸落在了每处路径"，而不是只改了一处。新增一条对外文本路径时，漏登记会直接让门禁变红。

## 模式 B：空输入比报错更危险

聚合 / 生成入口的第一道闸必须是 **"有效源数 ≥ 1"**：

```python
def require_nonempty_sources(sources):
    try:
        empty = len(sources) == 0
    except TypeError:
        empty = not sources
    if empty:
        raise RulingError("有效源为空：不允许以 0 个源生成页面（空壳页风险）")
```

内部实战踩过的坑：模型收到 0 个源仍会输出一段看似完整的 Markdown，且能过"字段齐全"
校验，于是静默覆盖掉完整旧版。显式失败比"优雅降级成空页"安全得多。

## 模式 C：相关性过滤先做同义扩展

字面匹配会误杀同义表述。过滤前先做同义扩展：

```python
SYNONYMS = {"复购": ["复购", "回购", "复购率", "复购提升"], ...}

def relevance_filter(docs, query, required=1):
    tokens = expand_query(query)          # 把"复购提升"扩展成 {复购, 回购, 复购率, ...}
    return [d for d in docs if sum(t in (d.get("text", d) or "") for t in tokens) >= required]
```

查询"复购提升"时，正文用"会员回购"写法的文档也能被召回，不再因字面不匹配被误杀。

## 三模式如何闭环

- **可测试**：`tests/test_rules_safeguards.py` 对三条模式各自给负向用例（空源必抛、
  同义写法必召回、漏登记必失败）。
- **可复跑**：与 `eval_cli.py` 的 CI 门禁同一条链路，改了链路必须过全量回归。
- **零真实数据**：同义词表用通用零售术语（复购 / 会员 / 新品 / 冷链 / 门店），真相源是
  合成 `data/store_facts.json`（演示品牌 12 家），与任何真实企业经营数据无关。

把"不漂移"从约定变成代码层闸，RAG 的口径才真的可靠。
