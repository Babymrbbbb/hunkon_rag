# 金首信（天鹅公主）AI 工作方向调整方案

> 目标：把金首信 AI 工作从「单点 AI 应用」调整为「围绕工厂 → 门店全链路系统对接」，
> 让 AI 工作方向对齐 FDE（前沿部署工程师）× 信息部双角色的重造思路。
> 公司现状（知识库可查事实）：母公司清远市金首信食品有限公司（洲心工业园），中央工厂 3000 余㎡，6S 管理 + ISO22000 认证，47 家门店（清远含连州40 / 广州含花都4 / 肇庆2 / 佛山1）。

---

## 一、现状诊断：AI 工作目前是什么样

| 维度 | 当前（单点 AI 应用） | 问题 |
|---|---|---|
| 数据 | 各系统数据割裂，无统一底座 | 工厂 ERP、门店收银、公域、私域各说各话 |
| AI 应用 | 知识库/经营分析/会员/内容/竞品（六大类） | 是「点」不是「链」，未嵌入工厂→门店全流程 |
| 工厂侧 | 中央工厂 3000 ㎡，但排产/要货靠经验 | 工厂数据未接入 AI，报废率/缺货率无 AI 优化 |
| 门店侧 | 店长用 AI 查标准/看分析 | 收银/库存数据未实时回流，AI 分析滞后 |
| 角色 | AI 应用架构师（偏工程） | 未体现 FDE × 信息部双角色的系统重造能力 |

**核心问题：AI 工作没有围绕「工厂→门店」的完整链条来组织，还是散点。**

---

## 二、调整方向：AI 工作往哪里靠拢

### 总目标

**从「六大类 AI 应用」升级为「一套覆盖工厂→门店全链路的 AI 整合系统」**：
```
工厂排产 → 智能要货 → 门店收银 → 公域/私域 → 营运分析 → 门店执行
   ↑___________ AI 贯穿全链路（数据统一底座 + AI 介入点）___________↓
```

### 具体调整（金首信应该怎么改）

#### 调整 1：先建「工厂→门店」数据统一底座（信息部职责）

| 动作 | 具体做什么 | AI 介入点 |
|---|---|---|
| 打通工厂 ERP 与门店收银 | 中央工厂生产数据、原料成本、库存 ↔ 门店销售实时回流 | 日清日结，次日自动生成分析 |
| 统一主数据 | 门店编码、SKU（面包/蛋糕/饮品）、会员 ID 一个数一个值 | 口径统一后 AI 才可信 |
| 接入公域（抖音/美团）订单 | 公域订单自动同步、核销、库存扣减 | 超卖/缺货预警 |
| 私域会员 OneID | 会员跨渠道识别、积分通兑 | 精准营销 |

#### 调整 2：AI 介入工厂侧（新增，重点靠拢方向）

| 环节 | AI 介入 | 预期价值 |
|---|---|---|
| **智能排产** | 基于门店销售趋势 + 节假日 + 天气 + 保质期模型，预测每款产品产量 | 计划达成率 ↑，报废率 ↓（对标多乐之日 98%） |
| **智能要货** | 按门店 7 日销售均值 + 库存水位，自动生成建议要货量 | 缺货率 ↓，库存周转 ↑ |
| **损耗预警** | 识别高报废门店/时段/品类，提前干预 | 年省损耗成本 |

#### 调整 3：AI 嵌入门店日常（已有，强化）

| 环节 | AI 介入 | 现状 → 调整后 |
|---|---|---|
| 门店问答 | 员工自然语言查标准/活动/供应链 | 已上线 → 补充工厂/供应链知识 |
| 经营分析 | 次日自动生成 + 异常雷达 | 已上线 → 加入工厂成本、报废数据 |
| 会员运营 | RFM 分层 + 券下发 | 已上线 → 与收银数据实时联动 |
| 内容/竞品 | 自动生成素材 + 竞品监控 | 已上线 → 对齐工厂新品节奏 |

#### 调整 4：角色叙事升级（FDE × 信息部双角色）

| 旧叙事 | 新叙事 |
|---|---|
| AI 应用架构师，交付六大类 AI 应用 | **FDE × 信息部双角色**：嵌入工厂与门店现场，重造系统对接数据流程，在 8 个环节介入 AI |
| 知识库/经营分析/会员/内容/竞品 | **工厂排产→智能要货→收银→公域→私域→营运分析**全链路 AI 整合系统 |
| 年省 5,800 工时 | 年省 5,800 工时 **+ 报废率下降 + 排产达成率提升** |

## 三、AI 工作方向调整对照表（旧 → 新）

| 旧方向 | 新方向 | 调整原因 |
|---|---|---|
| 知识库检索（门店侧） | 知识库 + **工厂/供应链知识** | 补齐工厂端，服务全链路 |
| 经营分析（门店侧） | 经营分析 + **工厂成本/报废/排产分析** | 从门店扩展到工厂 |
| 会员运营（私域） | 会员运营 + **收银/公域数据实时联动** | 数据打通后精准 |
| 内容生产（公域） | 内容生产 + **对齐工厂新品/排产节奏** | 工厂与门店协同 |
| 竞品监控 | 竞品监控 + **供应链/原料情报** | 竞品维度扩展到上游 |
| （无） | **智能排产 / 智能要货 / 损耗预警** | 新增工厂侧 AI 介入点 |

## 四、落地路线（金首信怎么改）

### 第一阶段：数据底座（1-2 个月）
- 打通工厂 ERP ↔ 门店收银（销售实时回流）
- 统一主数据（门店/SKU/会员）
- 接入公域订单 + 私域 OneID

### 第二阶段：AI 介入工厂侧（2-4 个月）
- 上线智能要货（基于销售均值 + 保质期模型）
- 试点智能排产（先 1-2 款爆品）
- 损耗预警看板

### 第三阶段：全链路 AI 整合（4-6 个月）
- 经营分析加入工厂成本/报废维度
- 知识库补充供应链知识
- 内容/竞品对齐工厂节奏
- 沉淀方法论（FDE × 信息部双角色）

## 六、与互联网同岗位的对齐（FDE × 信息部）

| 互联网做法 | 金首信落地 |
|---|---|
| FDE：嵌入客户现场诊断瓶颈 | 驻场工厂 + 门店，观察排产/要货/收银真实流程 |
| FDE：问「用户要做什么决策」 | 问「工厂要产多少、门店要进多少、总部要看什么」 |
| 信息部：统一主数据 | 门店/SKU/会员一码通 |
| 信息部：打通 ERP/POS/CRM | 工厂 ERP ↔ 门店收银 ↔ 公域 ↔ 私域 |
| 信息部：供应链协同 | 智能排产 + 智能要货 |
| FDE：AI-native 交付 + go-live 驻场 | AI 嵌入 8 个环节 + 店长/工厂主管培训 |
| FDE：沉淀可复用资产 | 365 条教训库 + 方法论博客 |
